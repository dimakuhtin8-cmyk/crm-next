# Обмін даними з 1С (Exchange API)

Документація REST API для синхронізації даних CRM із зовнішніми системами
(1С:Підприємство, Excel-імпортери та інші обробники).

API працює в двох напрямках:

- **Вивантаження** (GET) — зовнішня система отримує змінені записи CRM
  (контакти, угоди, задачі) для актуалізації свого обліку;
- **Завантаження** (POST) — зовнішня система передає свої дані, які
  створюються або оновлюються в CRM (upsert).

## Базова URL

```
https://crm-next-5mij-six.vercel.app/api/v1/exchange/
```

Сутності (entity): `contacts`, `deals`, `tasks`.

## Автентифікація

Автентифікація за **ключем обміну** (API-ключ), без cookie-сесій.
Ключ генерується в CRM: **Налаштування → Інтеграції → Обмін з 1С →
«Згенерувати ключ»**. Ключ показується один раз — збережіть його.

Передавайте ключ одним із заголовків:

```
X-Api-Key: <ключ>
```

або

```
Authorization: Bearer <ключ>
```

Опційний заголовок `X-Tenant-Id: <id тенанта>` — підказка для прискореного
пошуку тенанта; значення все одно перевіряється, невірна підказка не дає доступу.

- Відсутній або невірний ключ → `401 Unauthorized`.
- **Ключ визначає тенанта**: усі дані ізольовані за тенантом — запити
  повертають і змінюють лише записи компанії, якій належить ключ.
- Ключ можна відкликати в тому самому розділі налаштувань («Відкликати») —
  після цього всі запити з ним отримують `401`.

## GET — вивантаження змінених записів

```
GET /api/v1/exchange/{entity}?since=<ISO-дата>&limit=<1..500>&offset=<0..>
```

Параметри (усі опційні):

| Параметр | Опис                                                                                                                              |
| -------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `since`  | ISO-дата часу (`2026-01-15T10:30:00Z`). Повертаються записи з `updatedAt >= since`. За замовчуванням — з усіх часів (1970-01-01). |
| `limit`  | Кількість записів на сторінку, 1..500 (за замовчуванням 100; значення поза діапазоном стискаються до нього).                      |
| `offset` | Зсув для пагінації (за замовчуванням 0).                                                                                          |

Відповідь `200 OK`:

```json
{
  "items": [
    {
      "id": "clx...",
      "firstName": "Іван",
      "lastName": "Петренко",
      "email": "ivan@example.com",
      "phone": "+380501112233",
      "company": "ТОВ Приклад",
      "externalId": "C-0001",
      "updatedAt": "2026-11-23T12:00:00.000Z"
    }
  ],
  "nextSince": "2026-11-23T12:00:00.000Z",
  "count": 1
}
```

- `items` — записи тенанта, відсортовані за `updatedAt` за зростанням;
  мінімальний набір полів + `externalId` + `updatedAt`.
- `nextSince` — максимальний `updatedAt` цієї сторінки (ISO). Для наступного
  запиту використовуйте `since = nextSince` **плюс 1 мілісекунда** або
  дедуплікуйте записи за `id`/`externalId` (фільтр працює як `>=`, тому
  межові записи можуть повторитися).
- `count` — кількість записів у `items`.

Поля `items` за сутностями:

- `contacts`: `id`, `firstName`, `lastName`, `email`, `phone`, `company`,
  `externalId`, `updatedAt`;
- `deals`: `id`, `title`, `value`, `currency`, `company`, `status`,
  `externalId`, `updatedAt`;
- `tasks`: `id`, `title`, `type`, `status`, `priority`, `dueDate`,
  `externalId`, `updatedAt`.

Приклад (curl):

```bash
curl "https://crm-next-5mij-six.vercel.app/api/v1/exchange/contacts?since=2026-11-01T00:00:00Z&limit=100" \
  -H "X-Api-Key: <ключ>"
```

## POST — завантаження даних (upsert)

```
POST /api/v1/exchange/{entity}
Content-Type: application/json
```

Тіло запиту:

```json
{
  "items": [
    {
      "externalId": "C-0001",
      "firstName": "Іван",
      "lastName": "Петренко",
      "email": "ivan@example.com",
      "phone": "+380501112233"
    },
    { "externalId": "C-0002", "firstName": "Олена", "company": "ТОВ Приклад" }
  ]
}
```

- Максимум **500 елементів** за запит (більше → `400`).
- Поле `externalId` опційне, але рекомендоване: це стабільний ключ зіставлення
  (код контрагента/документа в 1С).
- Пошкоджений елемент (некоректні дані) **не блокує** решту: він потрапляє в
  `report.errors` зі своїм індексом, інші елементи опрацьовуються далі.

Відповідь `200 OK`:

```json
{
  "report": {
    "created": 2,
    "updated": 1,
    "skipped": 0,
    "errors": [
      { "index": 3, "message": "Невірні дані: email — Невірний email" }
    ]
  }
}
```

- `created` — створено нових записів;
- `updated` — оновлено існуючих;
- `skipped` — існуючі записи без змін (дані збіглися);
- `errors` — поелентні помилки: `index` — індекс елемента в масиві `items`
  (починаючи з 0), `message` — опис помилки.

### Правила зіставлення (upsert)

Запис шукається в порядку пріоритету:

1. **`externalId`** — точне значення (головний ключ);
2. **Контакти**: `email` (без урахування регістру) або `phone`
   (порівняння тільки за цифрами: `+38 (050) 111-22-33` = `380501112233`);
3. **Угоди та задачі**: точний збіг `title`.

Якщо запис не знайдено — створюється новий. Знайдено — оновлюються **лише
поля, передані в елементі** (відсутні поля не змінюються).

### Поля за сутностями

**contacts** — `firstName*` (обов'язкове при створенні), `lastName`, `email`,
`phone`, `company`, `position`, `notes`, `source`, `status` (`active` |
`inactive` | `lead` | `client`, за замовчуванням `active`), `externalId`.
При оновленні достатньо ключа зіставлення (`externalId`/`email`/`phone`) та
полів, які змінюються.

**deals** — `title*`, `value` (число), `currency` (за замовчуванням `UAH`),
`company`, `notes`, `status` (`open` | `won` | `lost`, за замовчуванням
`open`), `externalId`, опційно `pipelineId`/`stageId`. Якщо воронку не
вказано — угода розміщується в першій воронці та першій стадії тенанта.

**tasks** — `title*`, `description`, `type` (`task` | `call` | `email` |
`meeting` | `follow_up`), `status` (`todo` | `in_progress` | `done` |
`cancelled`), `priority` (`low` | `medium` | `high` | `urgent`), `dueDate`
(ISO `2026-03-15T10:00:00Z` або `15.03.2026`), `externalId`.

Обов'язкові поля позначені `*`. Невідомі поля ігноруються.

Приклад (curl):

```bash
curl -X POST "https://crm-next-5mij-six.vercel.app/api/v1/exchange/deals" \
  -H "X-Api-Key: <ключ>" \
  -H "Content-Type: application/json" \
  -d '{"items":[{"externalId":"DOC-42","title":"Угода з ТОВ Приклад","value":15000,"currency":"UAH","status":"open"}]}'
```

## Формат помилок

| Статус | Коли                                         | Тіло                               |
| ------ | -------------------------------------------- | ---------------------------------- |
| `400`  | Невірний параметр запиту або тіло            | `{ "error": "..." }`               |
| `401`  | Відсутній/невірний ключ, або ключ відкликано | `{ "error": "Не авторизовано" }`   |
| `404`  | Невідома сутність (не contacts/deals/tasks)  | `{ "error": "Невідома сутність" }` |
| `500`  | Внутрішня помилка                            | `{ "error": "..." }`               |

Поелентні помилки завантаження повертаються в `report.errors` зі статусом
`200` — успішні елементи вже збережені.

## Обмеження та рекомендації

- Розмір батчу: до **500 записів** за запит (для перенесення великих масивів
  розбивайте на пакети).
- Темп запитів: орієнтовно **до 1 запиту на секунду**. API не має жорсткого
  rate-limit, але часті запити можуть бути обмежені на рівні платформи.
- Для інкрементальної синхронізації ведіть «водяний знак»: після кожного
  вивантаження зберігайте `nextSince` і передавайте його в `since`
  наступного запиту (додайте 1 мс або дедуплікуйте межові записи).
- Часовий пояс: усі дати в ISO 8601 з UTC (`Z`). `dueDate` задач також
  приймається у форматі `dd.mm.yyyy`.

## Ізоляція даних

Усі дані ізольовані за тенантом (компанією): ключ обміну належить одному
тенанту, і через API доступні лише його контакти, угоди та задачі.
Записи інших компаній недоступні незалежно від параметрів запиту.
